Build once, serve static

The index is immutable. The build reads the site, writes one .rsx artifact and publishes it with the HTML; serving a query is a read of that file, not a write to a database.

Cache the artifact, not queries

Because the artifact carries a checksum, a deploy can upload a new name and switch the page to it. The old artifact stays valid for clients that are still loading it, so there is no cache-invalidation race between the index and the pages it describes.

Rebuild when the corpus changes

A changed page requires a new artifact. The build is deterministic: the same input tree produces the same checksum, which makes it safe to run in CI and compare against the artifact in production.

One artifact, many clients

The same file works in the browser through WASM, in a Worker for shard reads and in the CLI for tests. There is no second implementation to keep in step with the first.
